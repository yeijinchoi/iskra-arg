# 디자인 규칙

지금까지 받은 디자인 피드백을 정리한 규칙이다. **새로 만들거나 고치는 화면은 모두 이 규칙을 따른다.** 피드백이 새로 생기면 이 문서에 추가한다.

---

## 0. 기본 원칙

- **진짜 있을 법한 사이트처럼.** "AI 같다", "AI스럽다"는 피드백이 여러 번 나왔다. 과한 그라데이션, 네온·글로우, 의미 없는 장식, 이모지는 쓰지 않는다. 실제 서비스의 화면 구조를 따른다.
- **레퍼런스는 레이아웃만 참고한다.** 다른 회사의 로고, 색, 문구는 쓰지 않는다. 카피처럼 보이면 안 된다.
- **라이트 모드 고정.** 다크 모드는 만들지 않는다.
- **기능 없는 장식 요소는 만들지 않는다.** 눌리지 않는 버튼이나 링크(퀵링크, 계정 찾기·비밀번호 찾기·고객센터 등)는 넣지 않는다. 배너나 푸터 같은 장식은 눌리지 않는 것이 분명해야 한다.
- **클릭할 수 있는 요소에는 반응이 있어야 한다.** 마우스를 올리면 글자 링크는 밑줄, 행이나 카드는 연한 회색 배경이 생긴다. 전환은 `.15s ease`로 준다.
- **모바일(폭 640px 이하) 수정이 PC에 번지면 안 된다.** 반대로 PC를 고치면 모바일도 같이 확인한다.

### 레퍼런스 원칙 (확정)
- 화면을 새로 만들거나 고칠 때는 **먼저 국내 최근 UI 디자인 이미지(핀터레스트 'OO UI 디자인' 검색)를 레퍼런스로 찾고, 고른 레퍼런스의 배치를 따른다.** 사이트 자체를 찾거나 임의로 배치를 정하지 않는다. 작업현황에 어느 레퍼런스를 따랐는지 적는다.

### AI 티 나는 패턴 금지 (2026-11-22 점검)
- **여러 사이트에 같은 틀을 색만 바꿔 쓰지 않는다.** 단체정보마당·부동산·총동문회·아카이브가 '그라데이션 히어로 + 반투명 일러스트 + 두 색 제목("○○, **이렇게 확인**하세요") + 벤토 카드'를 똑같이 써서 AI가 만든 티가 났다. 사이트마다 실제 그 유형의 구성을 따른다.
  - 정부 민원 포털: 경로 표시 → 제목·설명 → 테두리 있는 조회 상자(라벨 + 입력 + 조회 버튼) → 공지사항 표 + 조회 안내.
  - 부동산 포털: 검색창이 맨 위, 지역 매물 현황 표, 최근 본 매물(실제로 본 매물이 쌓임), 계약 전 확인 순서.
  - 대학 동문회: 2단 상자(동문 찾기 / 동문회 소식), 사무국 정보. 각진 상자와 점선 목록.
  - 신문 아카이브: 명조 제호와 이중선, 가운데 검색, 소장 현황·지면 구성·소식 3단.
- **모바일 앱이 원형인 서비스는 모바일 앱 화면 구성을 따른다.** 즐겨찾기의 학사포털은 대학 커뮤니티 앱(시간표 격자, 게시판 목록), 카페 근무표는 교대근무 달력 앱(오늘 근무, 주간 띠, 요청 목록), 사전은 사전 앱(머리줄 검색창, 표제어 카드, 단어장). PC에서는 앱 폭(480px) 가운데 정렬, 섹션은 흰 바탕에 회색 선으로 나눈다. 레퍼런스는 배치만 참고하고 색·문구는 이 게임 것을 쓴다.
- 그라데이션 배경·그라데이션 테두리·색 있는 글로우 그림자·튀는(오버슈트) 움직임은 쓰지 않는다. 메신저·버튼은 단색, 그림자는 무채색.
- 기능 없는 장식 칩·태그('반출 관리', '내부망 전용' 같은)는 넣지 않는다.

## 1. 색

### 선과 테두리: 무채색만
- 테두리 `#E0E0E0`, 구분선 `#E6E6E6`.
- 포인트 색(빨강, 분홍, 파랑 등)으로 선이나 테두리를 그리지 않는다.
- 입력칸에 포커스가 가도 밑줄 색과 굵기가 바뀌지 않는다.
- 선택한 줄 앞에 색 세로줄 같은 강조선도 넣지 않는다.
- 면 구분은 선보다 배경 명도 차이로 한다.

### 배경 강조: 무채색만
| 용도 | 색 |
|---|---|
| 페이지 바탕 | `#F3F3F3` |
| 콘텐츠 상자 | `#FFFFFF` |
| 마우스 올림, 선택한 줄 | `#F0F0F0` |
| 안 읽은 줄 | `#F7F7F7` (굵은 글씨와 포인트 색 점으로만 구분) |
| 보조 버튼 배경 | `#EEEEEE` (글자는 기본 글자색) |

연분홍이나 연빨강처럼 포인트 색을 옅게 만든 배경은 쓰지 않는다.

### 포인트 색
- 포인트 색은 꼭 필요한 곳에만 쓴다: 주 버튼, 안 읽음 점, 토글, 체크, 브랜드 로고.
- **특정 선택지만 색으로 강조하지 않는다.** 노란 의심 선택지가 "이걸 눌러야 한다"고 종용하는 것처럼 보였던 사례가 있다. 선택지는 전부 같은 모양으로 둔다. 아이콘에 깜빡이는 점으로 유도하는 것도 하지 않는다.
- **배경색을 쓰지 않는다(확정, 흰색·아주 옅은 라이트그레이만).** 색이 도는 바탕(리넨·종이·돌 같은 틴트), 연한 색 칩·알약 메뉴, 색 번짐이 AI 티를 내는 주범이다. 사이트 바탕·머리줄·상자·섹션은 모두 흰색이고, 구분은 무채색 선(`#E6E6E6`)과 여백으로 한다. 포인트 색은 버튼·링크·선택된 메뉴 글자에만 쓴다. 입력칸·칩·시간표 칸은 흰 바탕에 회색 테두리. 마우스 올림 반응만 연한 회색(`#F5F5F5`).
- 사이트별 고유 포인트 색을 지킨다(바탕이 아니라 버튼·링크 색). 채도 높은 범용 파랑·청록과 보라·라벤더는 쓰지 않는다.
  - 이스크라(검색·메신저): 차분한 블루 `#1E5FC2`(로고 색). 메신저도 단색.
  - 노을메일: 빨강 계열 포인트, 선과 바탕은 무채색.
  - 라덴통상 ERP: 포인트 `#0D7480`, 잉크 `#1F3038`.
  - 단체정보마당(정부 포털): 포인트 항구 파랑 `#2C5877`, 잉크 `#1D2530`.
  - 이스크라 부동산: 포인트 짙은 청록 `#06525C`.
  - 총동문회·학사포털(같은 대학): 포인트 장밋빛 갈색 `#9A3C4C`, 잉크 `#2C2325`.
  - 도렌통신 아카이브: 버튼·잉크 먹색 `#181715`, 명조 제호.
  - 연합회 게시판: 포인트 호두 갈색 `#7A4A2C`.
  - 공공기록 열람센터: 포인트 남색 `#1F2B4D`.
  - 카페 소베크 근무표: 포인트 초록 `#456F3A`, 잉크 `#2A1D17`.
  - 바르니아어 사전: 포인트 황토 `#8C6418`, 잉크 `#29251E`.
  - 다나 프로필 원 바탕은 라벤더 대신 무채색 `#ECE8E2`(슬라임 그림은 그대로).
- 웜톤 크림과 애매한 주황 조합은 쓰지 않는다.

## 2. 면, 상자, 그림자

- **영역(상자·카드·패널·섹션·창)은 모서리를 둥글리지 않는 것이 기본이다(확정).** 둥근 영역도 AI 티의 원인이다. 버튼·입력칸·칩·아바타 같은 작은 조작 요소만 작게 둥글린다. **단, 따르는 레퍼런스에 둥글기가 있으면 레퍼런스와 비슷한 둥글기를 써도 된다**(예: 학생 포털 앱 타일 12px, 단어장 카드 16px, 공공포털·구청 검색창 알약형, 국내 로그인 입력칸 6px).
- **바탕은 흰색이나 아주 옅은 라이트그레이만 쓴다(확정).** 색이 도는 바탕은 쓰지 않는다.
- **같은 영역의 흰 덩어리는 하나로 합친다.** 목록과 읽기창이 따로 떠 있으면 어색하다. 푸터는 그 흰 상자 바로 아래에 둔다.
- 그림자는 무채색으로 은은하게 준다. 예: `0 20px 50px rgba(0,0,0,.08)`.
- **글래스모피즘**
  - 반투명 흰색에 `backdrop-filter: blur(24px) saturate(160%)`를 주고, 테두리는 없앤다.
  - 뒤에 비칠 배경이 필요하면 아주 은은한 번짐을 **최대 2개**만 둔다.
  - 번짐의 진하기는 20% 이하로 하고, 가장자리로 갈수록 여러 단계로 서서히 사라지게 한다.
  - 진한 덩어리나 세 개 이상의 번짐은 세련되지 못하다는 피드백을 받았다.
  - 글을 읽어야 하는 창(안내창 등)은 불투명도를 높여서(약 .94) 뒤 글자가 비치지 않게 한다.

- **화면은 가장자리까지 꽉 채운다.** 브라우저 틀과 각 화면 배경 양옆에 빈 띠를 두지 않는다. 대신 탭, 떠 있는 버튼(메신저·BGM·스크랩)은 화면 가장자리에서 띄운다(PC 기준 약 28px).
- 노을메일 메일 목록과 읽기창은 모서리를 둥글리지 않는다(각진 흰 상자). PC에서는 오른쪽 메일 영역(타이틀·읽기창·목록)을 하나의 흰 영역으로 만든다.
- **목록형 안내문**(안내창 등)은 가운데 정렬하고 글머리 기호를 쓰지 않는다. 항목 사이는 라이트그레이 점선(`1px dashed #E0E0E0`)으로 나눈다. 줄은 문장 단위로 끊어서 한 단어만 다음 줄로 넘어가지 않게 한다.

## 3. 글자

- **볼드를 남발하지 않는다.** 한 화면이 전부 볼드면 정신없다.

| 요소 | 굵기 |
|---|---|
| 본문, 라벨, 옵션(체크, 토글 옆 글자) | 400 |
| 보조 버튼, 보조 안내문 | 500 |
| 주 버튼 | 600 |
| 제목 | 700 |

- 같은 줄에 놓인 요소는 글자 크기를 맞춘다(예: 로그인 상태 유지와 새 메일 알림 모두 13px).
- **너무 크게 만들지 않는다.** PC에서 화면과 버튼이 크다는 피드백이 여러 번 나왔다.
  - 카드 최대 너비 440px.
  - 입력 글자 15px.
  - 버튼 13.5px, 높이 42px.
  - 버튼 사이 간격 8~10px.
- 모바일 입력칸 글자는 16px로 둔다(아이폰 자동 확대 방지).
- 글자는 11px보다 작게 쓰지 않는다. 회색 글자도 읽을 수 있는 대비를 유지한다.

## 4. 이미지와 아이콘

- **이미지는 힉스필드로만 생성하거나 다시 생성한다.** 직접 그리거나 내용을 편집하지 않는다. 크기를 줄인 사본만 허용한다.
  - **예외: 미니게임의 도트 캐릭터는 직접 찍는다.** 따로 생성한 캐릭터 그림은 서로 픽셀 크기·각도·비율이 달라 일관성이 없었다. 캐릭터는 배경과 같은 픽셀 밀도(배경 한 칸 = 32px, 캐릭터 32×48)와 같은 각도(위에서 비스듬히 내려다본 정면·뒷모습·옆모습)로 코드에서 한 픽셀씩 그리고, 같은 외곽선 색·그림자 규칙을 쓴다. 옆모습은 디테일을 잡지 않고 둥근 얼굴에 'ㅣ'자 눈만 찍는다. 걷기는 4방향 × 3프레임(서기·왼발·오른발)으로 번갈아 움직이고, 앉아 있는 손님은 2프레임으로 숨을 쉰다. 배경 맵은 그대로 힉스필드로 만든다.
- 위치나 잘림이 어긋나면 이미지 대신 CSS(`background-position`, `background-size`)로 맞춘다. 다나 슬라임 프로필을 위아래 가운데로 맞춘 것이 그 예다.
- 그림체는 **도트(픽셀) 아트**로 통일하고, `image-rendering: pixelated`를 쓴다.
- 인물 이미지는 어느 나라든 여러 인종이 섞여 있어야 한다.
- 캐릭터와 마스코트는 차분하게 만든다. 스파크, 볼터치, 화려한 색 같은 장식이 과하면 안 된다.
- 아이콘은 이모지를 쓰지 않고, 선 굵기가 일관된 SVG로 만든다. 파비콘은 각 사이트의 심볼 로고를 쓴다.

## 5. 연출

- 화면 전환은 은은한 페이드와 짧은 슬라이드로 한다. 튀는 스케일 애니메이션은 쓰지 않는다.
- **컷씬과 엔딩은** 검은 화면, 프레임 없는 도트 그림, 가운데 한 줄 문장, 점선 버튼으로 만든다. 둥근 플로팅 카드 모달은 쓰지 않는다.
- **수집 노트는** 영수증 모양으로 만든다: 위아래가 톱니처럼 뜯긴 흰 종이, 점선 구분선과 점선 리더로 이은 항목, 이중선 아래 총계, 바코드. 종이는 짧게 위에서 내려오듯 나타난다. **모양만 영수증이고 문구는 수집 노트 그대로 둔다**(손님·합계·감사 인사 같은 영수증 말투를 쓰지 않는다). 디자인 지시는 문구까지 바꾸라는 뜻이 아니다.
- **미니게임(카페 대타)은** 쯔꾸르(RPG 메이커) 화면을 따른다: 검은 바탕 위 16:9 탑다운 도트 맵, 칸 단위 이동, 화면 아래 진한 반투명 대화창(흰 테두리·이름·▼), 오른쪽 선택창(▶ 커서). 모바일은 방향 패드와 '말 걸기' 버튼.
- **알림은** 글래스 OS 알림 스타일로 통일한다. 사이트별 아이콘을 쓰고, 누르면 해당 화면으로 이동한다.
- 글리치나 깜빡임 효과는 짧게 쓴다(광과민성 고려).
- **하루가 바뀔 때(잠들기)는** 브라운관 모니터가 꺼졌다 켜지는 효과를 쓴다. 꺼질 때는 화면이 밝은 가로줄로 접혔다가 점으로 사라지고, 1초 정도 어두웠다가 켜질 때는 반대로 펼쳐진다. 밝아지는 순간은 한 번만, 1초 안에 끝낸다. 움직임 줄이기 설정에서는 검은 화면으로 서서히 어두워졌다 밝아지는 것으로 대신한다.

## 6. 게임 속 표기

- 게임 세계의 언어 표기는 '한국어'가 아니라 '도렌어', '바르니아어'다.
- 실제 회사명, 실제 로고, 실제 서비스 문구는 쓰지 않는다.

## 7. 확인 방법

- 바꾼 화면은 PC(1280px)와 모바일(390px) 두 폭에서 스크린샷을 찍어 확인한다.
- 확인할 것:
  - 선, 테두리, 배경 강조에 색이 들어갔는지
  - 볼드를 남발했는지
  - 크기가 과한지
  - 흰 덩어리가 쪼개졌는지
  - 기능 없는 요소가 있는지
